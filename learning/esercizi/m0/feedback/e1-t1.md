## B1 — output

**Cosa hai scritto:**
```
user.name = 'Sara'
copy.address.city = undefined;
user === copy = false;
user.address === copy.address = false
```

**Cosa fa davvero, passo passo** (con i cassetti numerati):
1. `const user = { name: 'Leo', address: { city: 'Milano' } }` crea due oggetti:
   il cassetto #1 `{ name: 'Leo', address: → #2 }` e il cassetto #2 `{ city: 'Milano' }`.
2. `const copy = { ...user }` crea il cassetto **nuovo** #3 e ci copia le proprietà di #1:
   `name: 'Leo'` (un valore) e `address: → #2` (**il bigliettino**, non l'oggetto).
3. `copy.name = 'Sara'` modifica il #3. Il #1 resta `'Leo'`.
4. `copy.address.city = 'Roma'` segue il bigliettino di #3, che porta al #2, e modifica il #2.
   Il #2 però è lo stesso cassetto che vede `user`.
5. Il log stampa: **`Leo Roma false true`**.

**Gli errori, uno per uno:**
- `user.name = 'Sara'` → in realtà è `'Leo'`. La tua stessa frase sul perché dice "`user.name` rimane uguale":
  output e spiegazione si contraddicono.
- `city = undefined` → in realtà è `'Roma'`. Inoltre hai scritto `copy.address.city`, ma il log stampa `user.address.city`.
  Il valore da prevedere era un altro.
- `user.address === copy.address = false` → in realtà è `true`.

**L'idea sbagliata dietro.** Hai letto "lo spread non copia gli oggetti annidati" come
"l'oggetto annidato **non c'è** nella copia", da cui `undefined`, oppure come "è un oggetto diverso", da cui `false`.

**L'idea giusta.** Lo spread copia **tutte** le proprietà di primo livello. Per quelle che contengono
un oggetto copia **l'indirizzo** e non l'oggetto. È come fotocopiare una rubrica: hai una rubrica nuova,
ma gli indirizzi scritti dentro portano alle stesse case. Se ridipingi una casa usando la rubrica
fotocopiata, chi usa l'originale trova la casa ridipinta.

**Domanda guida.** Nella riga del log ci sono quattro espressioni. Per ognuna: parte da `user` o da `copy`?
E quale cassetto legge alla fine?
