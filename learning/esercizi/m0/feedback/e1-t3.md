## B2 ✘ — ordine delle chiavi (stesso errore del tentativo 2)

**Cosa fa davvero, passo passo:**
1. `...base` → nasce `size: 'M'` (posto 1) e poi `color: 'red'` (posto 2).
2. `...extra` → `color` esiste già, quindi cambia solo il valore in `'blue'` e **resta al posto 2**. `price` è nuova e va al posto 3.

**L'idea sbagliata dietro.** "Chi scrive per ultimo va in fondo." È la stessa idea del tentativo 2 (B2),

una svista: è un modello che non è ancora cambiato.

**L'idea giusta.** Ci sono due regole distinte, e vanno tenute separate:

## B3 ½ — destructuring con rest
**Cosa hai scritto:** `'password', ['pwd', true], 'pwd', 'default'`
**Reale:** `password { name: 'pwd', required: true } pwd default`

`type`, `name` e `missing` sono giusti. **`others` no:** il rest dentro `{ }` raccoglie le proprietà rimaste
in un **oggetto**, con le loro chiavi, non in un array di valori.
- `const { a, ...resto } = oggetto` → `resto` è un **oggetto**;
- `const [a, ...resto] = array` → `resto` è un **array**.

La forma del rest segue le parentesi che usi: graffe → oggetto, quadre → array.

**Sul perché.** "name rimane pwd perché sovrascritto da name presente nella funzione" non è corretto.
`name = 'anon'` è un **default**, e scatta solo se `others.name` è `undefined`. Qui `others.name` vale `'pwd'`,
quindi il default non serve. `missing` invece non esiste in `others`, quindi vale `undefined` e scatta il default.
È la stessa regola di B5: l'avevi giusta lì, ma non l'hai riconosciuta qui.

## B4 ✘ — event loop (la regola c'è, l'applicazione no)
**Cosa hai scritto:** `1 4 5 3 2 6`
**Reale:** `1 4 7 3 5 2 6`

Ci sono due errori:
1. **Manca il `7`.** `console.log(7)` è l'ultima riga **sincrona**, quindi esce subito dopo `4`.
   Dimenticare una riga significa non aver scorso il codice dall'alto in basso.
2. **`5` prima di `3`.** I microtask escono **in ordine di arrivo in coda**:
   - riga 3: `.then(...)` mette **3** in coda (Promise già risolta);
   - poi parte la funzione async, stampa 4 e arriva all'`await` → mette **5** in coda, **dopo** il 3.

| Passo | Stampa | Microtask | Task |
|---|---|---|---|
| `log(1)` | 1 | | |
| `setTimeout` 2 | | | 2 |
| `.then` 3 | | 3 | 2 |
| async: `log(4)`, `await` | 4 | 3, 5 | 2 |
| `log(7)` | 7 | 3, 5 | 2 |
| microtask | 3, 5 (che aggiunge il task 6) | | 2, 6 |
| task | 2, 6 | | |

**Il nodo vero.** Il tuo perché ("prima il sincrono, poi i microtask, poi il resto") è giusto per la terza
volta di fila, ma la previsione non lo segue. Sapere la regola non basta: va **eseguita con la tabella**,
riga per riga, senza saltare.

**Domanda guida.** Se sposti `Promise.resolve().then(() => console.log(3))` **dopo** la funzione async,
cosa cambia?
